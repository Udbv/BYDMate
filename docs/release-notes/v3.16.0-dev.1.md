## BYDMate Waze 3.16.0-dev.1 (development pre-release)

**Development channel.** First build with lane guidance.

### New
- **Lane guidance on the instrument panel** (Settings -> Display -> HUD, on by default for the
  AR-HUD type). The lanes at the junction ahead are read from the navigator window and drawn by the
  factory panel: how many lanes there are, which directions each allows, and which ones the route
  takes. Eight slots, glyph codes as the factory navigation uses. The strip clears after 12 s
  without an update and when the route ends.

### How it works
Lane output goes to the same instrument-panel features that already carry the maneuver arrow, which
is the only channel that reaches the glass on the Tang L. No new daemon transaction was needed: the
25 feature writes are sent individually, and only when the lanes change.

### Known limitation, and what to check in the car
Waze draws its lane arrows as images. Directions are taken from each lane's accessibility
description where the build provides one; if it does not, the strip still shows the correct number
of lanes but without arrow directions. The reader logs what it found on every change
(`WazeLaneReader`) and the settings diagnostics dump includes a lane line, so one drive past a
multi-lane junction will show whether the labels are usable or whether the arrows need to be
classified from pixels instead.

Capture with:

```
adb logcat -v time HudLaneWriter:I WazeLaneReader:I HudPushLoop:I NavGuidanceHub:I *:S
```

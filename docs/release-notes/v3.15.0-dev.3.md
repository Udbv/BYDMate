## BYDMate Waze 3.15.0-dev.3 (development pre-release)

**Development channel only.** Second field-debugging build for the BYD Tang L EV 2025 (DiLink 150).
Export-warning auto-close is confirmed working in the car (dev.2). The HUD still showed nothing
in dev.2 although the gateway offered our service and frames left with rc=0, while openbyd 2.4.3's
HUD test renders on the same glass. This build reproduces openbyd's channels, each switchable, so
the next car test can bisect which one the glass reads.

### Fixed
- The dev.2 claim that the Tang L map opens a different service key was wrong (arithmetic slip);
  everyone uses `0xB010A00010000`, the SDK's `HUD_NAVI_INFO_SERVICE_SERVICE_ID`. The invented
  key is gone.
- AR-HUD road name no longer carries the "| HH:MM min | HH:MM" suffix (that glass has its own
  time fields).

### Added (AR-HUD type, Settings -> Display -> HUD)
- **HUD frame**: Tang L field set plus vehicle speed, lon/lat, altitude, heading, guide line and
  guide point from the last GNSS fix (what the factory map and openbyd send).
- **Factory-map context**: the launcher-map session on services 7, 0x8202, 0xC..0xF (port of
  openbyd's default `LauncherMapCnStrategy`) with BYDMate's guidance values.
- **Guidance to the instrument panel**: icon, distance, remaining route and navigation status
  through the instrument features (port of openbyd's CAN channel) via the helper daemon.
- Info-level logs for all three: `HudPushLoop`, `HudLauncherMapCtx`, `HudInstrumentFids`.

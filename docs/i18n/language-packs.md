# Pluggable language packs (design, 2026-09-06)

Goal: every language is one self-contained pack; adding a language touches one Kotlin line; a
tool tells the developer exactly which translations a feature change left missing or stale.
Companion to `localization-framework-design.md`.

## 1. What a pack is

Identified by a BCP-47 tag (`uk`).

```
app/src/main/
  assets/i18n/
    languages.json                       # manifest (one file for all packs)
    uk/
      prompts.json                       # LLM prompts / tool descriptions / errors (optional, falls back)
      ledger.json                        # key -> sha1 of the reference text at translation time (generated)
  assets/navi/phrases/
    uk.json                              # parser tables for Yandex/Waze text in that language (optional,
                                         # NOT tied to the UI language: all files load always)
  res/values-uk/strings.xml              # UI strings (mandatory)
  kotlin/.../voice/lexicon/uk.kt         # voice lexicon (optional; RU/EN only today, ASR is RU-only)
  kotlin/.../i18n/AppLanguage.kt         # one enum entry (mandatory)
```

| Part | Mandatory | Fallback when missing |
|---|---|---|
| `AppLanguage` entry (tag, nativeLabel, promptFallback, voice, apiTag) | yes | build fails (manifest test) |
| `res/values-<tag>/strings.xml` | yes, 100% keys or allowlisted | Android would fall back to `values/` (Russian): that silent bug is what the parity test turns into a hard failure |
| `assets/i18n/<tag>/prompts.json` | no | chain declared in the enum: `uk -> ru`, `be -> ru`, `pl/pt/zh -> en`; merged key by key, never file by file |
| `assets/navi/phrases/<tag>.json` | no | none: Waze may run in `uk` while the UI is `en`, so every present file is loaded |
| voice lexicon | no | `AppLanguage.voice` maps to `VoiceLang.RU`/`EN` |
| `ledger.json` | yes | generated by the tool, never hand-written |

`languages.json`:
```json
{ "reference": "ru",
  "packs": [
    { "tag": "uk", "nativeLabel": "Українська", "status": "beta",
      "promptFallback": "ru", "voice": "ru", "apiTag": "uk-UA",
      "naviPhrases": true, "allowUntranslated": ["app_name", "dashboard_trip1_label"] } ] }
```
`status`: `complete | beta | draft`. Draft packs are hidden from Settings but compiled and tested.

`prompts.json`: flat `{ "system.persona": "...", "tool.weather.desc": "...", "err.no_key": "..." }` with
`{name}` placeholders; a `PromptCatalog` object replaces the literals in `AgentOrchestrator`,
`AgentPersona`, `AgentTools`, `WeatherClient`, `AgentCommandCatalog`.

`navi/phrases/uk.json` mirrors the `add(GAODE_x, phrases...)` blocks in `NavManeuverCodes.kt` and the
unit regexes; order is significant (see the comment on "кільці" in `NavManeuverCodes.kt`), so phrases
are ordered arrays, never maps:
```json
{ "source": ["waze"],
  "maneuvers": [ {"code": "UTURN_RIGHT", "phrases": ["розверніться праворуч"]}, ... ],
  "units": { "km": ["км"], "m": ["м"], "hourMin": "(\\d+)\\s*год\\s*(\\d+)\\s*хв", "min": "(\\d+)\\s*хв" } }
```

## 2. Completeness model (machine-checked)

Android gives for free: resource fallback, `translatable="false"`, lint `MissingTranslation`. Not enough:
the lint baseline (`app/build.gradle.kts:74`) freezes existing gaps, lint ignores `assets/`, lint cannot
detect STALE translations (reference edited, translation not: commit `92466cd` touched `values-en` by two
lines only), and the fallback target is Russian so a gap is invisible on the device.

JVM test `app/src/test/kotlin/com/bydmate/app/i18n/LanguagePackParityTest.kt` (project root located like
`CommandTranslatorTest.kt:34-36`):
- `manifest_matches_AppLanguage_and_res_dirs`
- `strings_no_missing_keys` (reference keys minus `translatable=false` minus `allowUntranslated`)
- `strings_no_extra_keys` (dead strings)
- `prompts_no_missing_keys` (partial allowed only when `status != complete`)
- `no_stale_translations` (ledger sha vs current reference sha)
- `placeholders_match` (`%1$s` / `{name}` counts)
- `no_cyrillic_literals_outside_allowlist` (the source-scan guard)
- `all_navi_phrase_files_parse_and_have_unique_codes`

Failure output is one table: `uk: 14 missing, 3 stale, 0 extra -> run ./gradlew :app:i18nReport`.

## 3. New feature workflow

Gradle tasks (registered in `app/build.gradle.kts`, implemented in `buildSrc`):
- `:app:i18nReport` prints missing / stale / extra per pack
- `:app:i18nTodo` writes `docs/i18n/todo/<tag>.md` per pack: `key | reference (ru) | current | hint`
- `:app:i18nDraft -Ptag=uk` copies reference text into the pack marked draft (optional `-Pmt=deepl`)
- `:app:i18nLedger` rehashes the reference text for keys you translated (commit the ledger diff)
- `scripts/i18n-check.sh` = `i18nReport` + the parity test; added to `.github/workflows/ci.yml`

Definition of Done for any PR touching a user-visible string:
1. Key added to `values/strings.xml` (ru) and to `assets/i18n/ru/prompts.json` if agent-facing.
2. `i18nReport` shows 0 missing for `complete` packs, or the key is deliberately draft-filled.
3. `i18nLedger` run; ledger diff committed.
4. CHANGELOG lists "i18n: N keys".
5. Parsed text (units, maneuvers) goes to `assets/navi/phrases/*.json`, never Kotlin.

Translators without Kotlin: fork, edit `values-<tag>/strings.xml` and `assets/i18n/<tag>/prompts.json`
from `docs/i18n/todo/<tag>.md`, open a PR; CI runs the parity test; the maintainer runs `i18nLedger`.
`docs/i18n/TRANSLATING.md` holds this procedure.

## 4. New language, worked example: Ukrainian

1. `./gradlew :app:i18nNewPack -Ptag=uk -Plabel=Українська -PpromptFallback=ru` creates
   `values-uk/strings.xml` (draft copies), `assets/i18n/uk/{prompts.json,ledger.json}` and the manifest row
   with `status: draft`.
2. Add `UK("uk", "Українська", promptFallback = RU, voice = VoiceLang.RU, apiTag = "uk-UA")` to
   `AppLanguage`. Only Kotlin change: Settings, LocaleBootstrap, LocaleContext, VoiceController,
   WidgetController, InsightsManager iterate `AppLanguage.entries`.
3. Translator fills strings; `i18nReport` reaches 0 missing; flip status to `beta`, then `complete`.
4. Parser tables: move the Ukrainian Waze block from `NavManeuverCodes.kt` into
   `assets/navi/phrases/uk.json` (first migration, proves the shape). No engine change;
   `NavPhraseTableLoader` reads every file, and `NavPhraseTablesGoldenTest` replays the existing Waze
   `uk` test fixtures to prove identical GAODE codes.
5. README language lists (`README.md` ~:747, `README.en.md` ~:575) generated from the manifest by
   `i18nReport`, with a test asserting every `complete` pack is mentioned.

## 5. Risks and non-goals
- Parser tables never depend on `AppLanguage`; drivers mix UI and navigator languages.
- RU stays the only ASR; `voice` only picks TTS/lexicon. No `uk` voice promised.
- Prompts in JSON can silently change model behaviour: golden test renders the `ru`/`en` system prompt.
- `values/` remains Russian (do not rename to `values-ru`, it breaks fallback for `ru-BY`).
- A reference edit invalidates every pack's ledger entry by design; `i18nLedger --accept-all` exists for typo fixes.
- Each pack labels itself in its own language.
- Non-goals: plurals framework, RTL, runtime pack download, Crowdin integration.
